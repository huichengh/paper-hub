# 研知引擎 PaperHub Research OS

从「论文汇总与对比」升级为**多文献证据融合的科研工作台**：上传中文 PDF → 自动识别元数据 → 全文按需抽取 → 划词批注与证据锚点 → 观点争议地图 → 候选研究机会 → 回到原文核验。

在线地址：https://huichengh.github.io/paper-hub/

## 当前已实现

### P0 数据底座

- **IndexedDB 持久化**：`papers`、`pdfFiles`、`pageTexts`、`annotations`、`claims`、`opportunities`、`settings`、`meta` 八个 store。
- **旧数据迁移**：首次打开检测 `localStorage` 旧库，提示先下载 JSON 备份，再一次性迁移；旧数据保留作为回退。
- **PDF 原文持久化**：导入时同时写入 IndexedDB，刷新页面后「检阅」不再要求重新选择文件（除非备份恢复或换浏览器）。
- **按需全文抽取**：勾选文献后点「全文抽取」，逐页写入 `pageTexts`；支持进度、取消、失败重试、刷新后保留已抽取页面。
- **证据锚点**：观点保存 `paperId + page + quote + anchor`；点击「定位原文」打开阅读器、跳转页码并高亮；无法精确锚定时明确退化为「跳页 + 摘录」，不伪装精确。

### P1 创新 MVP

- **学术观点争议地图**：研究问题 + 研究对象/行业/时间/情境条件；观点分「支持 / 反对 / 条件不同 / 证据不足」；支持手工新建、检阅模式选中原文转观点、编辑、确认、删除、按文献筛选。
- **证据可追溯**：每条观点显示来源文献、页码、原文摘录；从 PDF 选区保存的观点带原文锚点，手工摘录会标记「人工摘录 · 待核对」。
- **文献 × 立场覆盖矩阵**：只反映当前导入库内的观点分布。
- **科研空白候选雷达**：基于库内观点冲突、条件差异和证据缺口生成候选卡片（草案）；不调用模型，不宣称「全领域首创」。
- **机会卡片字段**：标题、候选研究问题、类型、证据强度标签、关联观点、限制/反向证据、待补检索词、备注；支持编辑、收藏、删除、筛选、导出 JSON / Markdown。
- **AI 可选**：不配置 AI 时 P0/P1 全部可用；配置 DeepSeek R1 后可按全文抽取带原文引用的观点（引文必须逐字匹配，否则丢弃），也可生成答辩追问。密钥只保存在页面内存。
- **AI 接入**：支持 DeepSeek R1 官方 `deepseek-reasoner`、本地 Ollama `deepseek-r1`、自托管 vLLM；兼容其他 OpenAI 接口。

### P2 研究设计与证据审计

- **研究方案生成器**：从研究机会或手工创建；字段包括研究目标、问题、对象/范围、理论框架、候选方法、变量/指标、数据需求、实施步骤、预期贡献、风险/缺失证据。
- **字段级来源标记**：每个板块标注「来自文献 / 基于文献的推断 / 我手工填写」；未确认方案显示“建议草案”，可标记为人工确认。
- **方法比较**：至少两种候选方法，按适用前提、局限、数据需求、成本/可行性并列；不生成专家评分或伪造调研数据。
- **版本与导出**：保存新版本（最多保留 10 个历史快照），导出 Markdown / JSON。
- **论文证据链审计**：粘贴综述/开题段落，按中文句号、分号、换行拆句；用库内观点与原文摘录做本地 n-gram 匹配，给出支持/部分支持/冲突/未找到证据的机器初判。
- **人工复核**：每条结论可改判、复制审阅意见、点击证据回跳 PDF；明确“未找到证据不等于结论错误”，不自动修改原文。
- **审计导出**：Markdown / JSON；显示库内观点数、文献数、全文抽取覆盖和人工复核状态。

### P3 研究助手

- **答辩追问**：本地模板生成 8–14 个追问；配置 DeepSeek R1 后可选“AI 生成追问”，发送前展示研究方案与观点预览，结果仍标为“AI 建议”。可填写回答、加入待办。
- **研究待办**：手工添加、从方案缺口生成、从审计未决项生成；支持完成/删除，存入方案本身。
- **方法迁移候选**：只从当前方案方法与关联观点的方法记录中提取；用户标注“待验证/可能可迁移/不可迁移”与边界说明，不检索外部学科。
- **可信度状态**：所有文献统一显示“未核验”，提供 Crossref 搜索入口，不伪造 DOI、撤稿或评分结果。
- **纪要导出**：问答、待办、迁移判断与可信度状态导出 Markdown。

### 保留的原有能力

- 前 8 页中文 PDF 元数据提取、分类、表格、筛选、排序、编辑。
- 全文检阅、文字层划词批注（五类）、8 个研究字段填充、框选图示。
- 21 项跨文献对比、Excel / CSV / JSON 导出与恢复。
- 原有批注锚点、局部/跨页高亮、重复打开同一 PDF 等修复继续有效。

## 代码结构

```
docs/
  index.html      界面、Research OS 导航与研究页面、弹窗
  app.js          数据流、上传、全文抽取、视图切换、导入导出
  db.js           IndexedDB 适配层、旧 localStorage 迁移、级联删除
  research.js     P1 争议地图 / 研究机会（手工 + 规则生成，无 AI 依赖）
  design.js       P2 研究方案生成器 + 证据链审计
  assistant.js    P3 研究助手：答辩问题、待办、方法迁移、可信度状态
  parser.js       中文 PDF 元数据解析规则
  fields.js       字段定义单一数据源
  reader.js       PDF 渲染、文字层、批注与证据锚点
  ai.js           OpenAI 兼容接口（API Key 仅内存）
  vendor/         pdf.js、SheetJS（本地文件）
```

## 本地运行

```bash
cd docs
python -m http.server 8823
# 打开 http://127.0.0.1:8823
```

也可直接双击 `docs/index.html`（Chrome / Edge）。

## 数据与隐私

- 默认全部在本地浏览器：PDF、字段、批注、全文、观点、机会、研究方案、审计与助手数据都在 IndexedDB / 方案对象内；不上传服务器。
- 迁移前页面会提示下载 JSON 备份；迁移失败自动回退旧存储。
- JSON 备份包含文献字段、批注、观点、机会、研究方案、审计结果，不包含 PDF 原文和逐页全文缓存。
- AI 抽取需用户主动配置并确认发送；发送前展示服务商、模型和真实片段预览；API Key 只存在当前页面内存，刷新后重新填写。

## 接入 DeepSeek R1

顶栏「AI 设置」内置三种 R1 入口：

| 方式 | Base URL | 模型名 | Key |
|---|---|---|---|
| DeepSeek R1 官方 API | `https://api.deepseek.com/v1` | `deepseek-reasoner` | 需要 |
| 本地 Ollama | `http://localhost:11434/v1` | `deepseek-r1:7b`（或 14b/32b） | 可留空 |
| 自托管 vLLM / SGLang | `http://localhost:8000/v1` | `deepseek-r1` | 视服务而定 |

Ollama 示例：

```bash
ollama pull deepseek-r1:7b
OLLAMA_ORIGINS=* ollama serve
```

注意：GitHub Pages 是 HTTPS，浏览器可能拦截对 `http://localhost` 的请求；本地模型建议直接本地打开 `docs/index.html` 或本地 HTTP 服务，并开启 Ollama 的 CORS。R1 的 `think` 段会被剥离后再解析 JSON；`deepseek-reasoner` 不发送 temperature 参数。

AI 目前用于：元数据字段抽取、按全文抽取带原文引用的观点（quote 必须逐字匹配，否则丢弃）、答辩追问。所有结果都标为待人工确认。

## 已知限制（未完成项）

- **P2 未接 AI 与 DOCX**：研究方案/证据审计为本地规则与手工路径；导出为 Markdown/JSON，未生成 DOCX。
- **P3 仅实现本地与 AI 追问**：答辩追问可选 R1；跨学科迁移只从库内方法记录提取，未接外部检索；文献可信度只显示“未核验”+ Crossref 搜索入口，没有 DOI/撤稿 API。
- **AI 观点抽取只读前 12 页**：更靠后的章节不会被抽取； quote 校验通过不代表观点概括一定准确，仍需人工核对。
- **证据审计是 n-gram 初判，不是语义判断**：可能漏匹配或误匹配，必须人工改判；不把“未找到证据”等同于结论错误。
- 扫描件 / 无文字层 PDF 只能手工录入或先 OCR。
- 全文抽取是逐页文本，不生成向量索引或语义检索；`pageTexts` 供后续证据检索/审计使用。
- JSON 备份不包含 PDF 原文，换设备后需重新选择 PDF；全文需重新抽取。
- 外部模型服务的 CORS、配额和费用由用户自行确认。

## 说明

本项目为个人学术研究辅助工具。所有观点、机会和 AI 输出都必须回到 PDF 原文核对；平台不会替用户宣称研究首创或替代系统综述检索。
